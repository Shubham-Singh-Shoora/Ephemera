# Security review — 13 October 2026

## Assessment

Engineering judgment, not an independent audit or security certification: **before 2/10; after 7/10 for a bounded local prototype; production readiness 3/10**. The local workflow is substantially safer because the server never receives document contents or room keys. The lower production rating reflects missing collaboration authorization, verified confidential compute, independent review, operational controls, and tested hosting resilience. A numerical score is only a summary of this scope.

Reviewed the frontend routes/components, encryption utilities, ingestion, memory handling, mock Bee, inference simulator, secret handoff, coordinator contract/client, deployment script, package dependencies, and existing tests. Tests use synthetic data and a local EVM. No public network penetration test, real TEE attestation, live Swarm deletion experiment, or production DDoS test was performed.

## Remaining limits and production gates

- **The public journey accepts no datasets.** It is a local training illustration, not a shared data room. The older isolated browser-search experiment displays plaintext to its local user; that warning does not imply public dataset access or an implemented trainer permission system. Browser extensions, screenshots, original files, swap, crash dumps, and previously made copies remain outside its erasure control. JavaScript strings and CryptoKey handles cannot be proven physically wiped. Closing releases app access; it does not prove global deletion.
- **Client compromise remains decisive.** Non-extractable keys prevent direct key export, not malicious same-origin code from requesting decryption. Nonced CSP, no third-party scripts, safe text rendering, no outbound production connections, frame denial, and no caching reduce exposure but do not defeat a compromised device, server build pipeline, or browser extension. Inline styles remain allowed; inline scripts need a nonce.
- **The product roles are data provider and AI training team.** The public journey illustrates provider-owned models, partner-led training, and trainer-led data requests. Its sample agreement does not enforce permissions. The isolated local room is single-user; tenant identity, matching, invitations, multi-user authorization, actual model training, and remote confidential compute are not implemented.
- **A future trained model is also an output channel.** Keeping raw files inside a verified environment does not prevent malicious training code or a released model from encoding sensitive information. Restrict executable code and outbound traffic, review outputs, and evaluate privacy-preserving training before releasing models. Arbitrary user code plus unrestricted model export is incompatible with an absolute no-leakage promise.
- **The coordinator trusts a simulator oracle.** It verifies the caller and state transition, not correct computation or hardware attestation. The owner still maps requests. References and receipts are public and may reveal metadata; arbitrary callers can encode information in public transaction inputs. Do not put real data in any calldata. Changes require a new contract deployment and reviewed migration; existing contracts are unaffected.
- **Availability is bounded, not guaranteed.** The 24-request local burst is a regression check, not a capacity benchmark or DDoS assessment. Production needs edge request/body/header limits, connection timeouts, rate limits, cost budgets, health monitoring, dependency isolation and an incident/runbook exercise. None is claimed as configured in a hosting account.
- **Future distributed storage conflicts with strict no-storage language.** Swarm retains encrypted chunks. Batch expiry affects eligibility for garbage collection, not proof every node deleted every copy. Live ingestion remains intentionally gated until postage and retention semantics are designed.
- **Legacy research adapters are not the product service.** Their returned strings/keys live in managed memory, they are for synthetic data, and their trusted Bee URL must not be exposed as a public request parameter. No TEE or medical/legal/financial suitability is claimed.

## Primary references

- [Swarm postage documentation](https://docs.ethswarm.org/docs/develop/tools-and-features/buy-a-stamp-batch/) describes non-deterministic storage duration and chunks becoming eligible for garbage collection. This is why the prior worldwide-deletion claim was removed.
- [Next.js security release guidance](https://vercel.com/changelog/next-js-may-2026-security-release) documents affected old framework lines and the need to patch. Installed versions were selected from the package registry and verified with a fresh audit, not pinned to that older advisory alone.
- [Chainlink confidential compute](https://chain.link/blog/chainlink-confidential-compute) describes a real confidential-compute architecture. A local hash and a JavaScript simulator do not implement it.
- [Hardhat simulated networks](https://hardhat.org/docs/reference/edr-simulated-networks) describes the local EVM used for adversarial coordinator testing.
